## Analyze

**The veil of ignorance test:** Would this material make sense and be useful to someone who knows nothing about the source ecology's specific projects, interests, or operational history? If yes, it passes. If it only makes sense in the originator's context, it gets stripped or generalized.

**What passed verbatim:**
- `node.md` — pure abstract structural position
- `relation.md` — pure abstract structural position
- `provenance.md` — pure abstract structural position
- Core concepts of every trunk protocol (FADE's four phases, noise floor's attenuation model, procedural memory's Graveyard/Gold structure, decomposition's middle-out principle, providence's inheritance model, omnibus's tag coordination, opportunistic separation's greedy principle)

**What was stripped:**
- All branch-specific subsections (Skyrim modding procedures, Art Shop checkout flow, US V3 constitutional specifics, Basketball Fan digest mechanics)
- All specific procedural memory entries (Windows-specific tool procedures, Nexus API patterns, MO2 handling)
- Domain-specific tag extensions (Skyrim grip surface tags, content generation tags)
- Named cross-branch examples (replaced with abstract descriptions of the same patterns)
- The Intake protocol (ROAD-specific hypervisory governance; too early for a fresh ecology)
- The concentric schema section of Contextual Providence (references specific formal architecture)

**What was generalized:**
- "Billy" → "the user" / "Brandi" throughout
- `billy.md` → `brandi.md` as bare identity template
- `schema.md` → empty template preserving the structural idea but containing no graph content
- Specific failure examples → general principles (e.g., "ACC compound failure chain" → "compound failure chains from skipping Find")
- Branch-specific examples in trunk docs → abstract pattern descriptions

## Decompose

The kernel decomposes into three layers:

**Layer 1 — Foundational positions (kernel/):** The structural atoms. Node sovereignty, intersubjective relations, deterministic provenance, molecular composition. These are domain-agnostic by nature. They describe how any system element works, not what system elements exist. Transferred with near-zero modification.

**Layer 2 — Operational protocols (trunk/):** The accumulated wisdom about how to work. FADE, noise floor, procedural memory, decomposition, providence, omnibus, opportunistic separation. These carry the source ecology's battle scars but express general principles. The veil stripped the scars and kept the principles — the structure of each protocol is preserved, the domain-specific examples and entries are removed.

**Layer 3 — Ecology-specific content (stripped):** Everything that makes the source ecology Billy's ecology rather than a general ecology. Project registries, branch characterizations, specific tool procedures, named collaborators, environment details. This layer is what Brandi's ecology will grow for itself.

**The key insight:** Layers 1 and 2 are separable from Layer 3 without losing structural integrity. The kernel's generality claim is exactly this: the structural logic and operational wisdom work regardless of what domain content fills them.

## Exploit

**Assembly:** Created the fork directory with:
- `CLAUDE.md` — bootstrap document for Brandi's ecology
- `brandi.md` — bare alpha entity template
- `kernel/` — 5 foundational documents (node, relation, provenance, node_schema, schema)
- `trunk/` — 7 operational protocols (FADE through opportunistic separation)
- `notes/` — this document (the fork's own provenance)

**What the fork tests:** Whether the kernel's patterns (sovereignty, FADE, procedural memory, adapter boundaries, omnibus tags, opportunistic separation) emerge naturally from a new user's domain-specific friction, or whether they require the source ecology's specific history to motivate them. If Brandi's ecology develops these patterns from her own work, the kernel is a genuine structural attractor. If the patterns feel forced or irrelevant, they were domain-specific all along.

**What was deliberately omitted:**
- Environment section (Brandi's machine is different)
- Safety protocol (will emerge from Brandi's own operational friction)
- Credentials management (will emerge when needed)
- Intake protocol (hypervisory; premature for a single-user ecology that hasn't yet grown multiple branches)
- Drive protocol (machine-specific)
